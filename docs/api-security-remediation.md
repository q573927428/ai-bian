# 敏感 API 密码保护方案（简化版）

> 2026-11-07 更新：登录弹窗已升级为账号和密码，新增必填 `CONFIG_EDIT_USERNAME`，密码沿用 `CONFIG_EDIT_PASSWORD`。账号或密码变更均使旧凭证失效；保留 24 小时 Cookie 和公开浏览。下文密码方案记录原设计，当前不提供自助注册。

> 按最新需求调整：页面和普通浏览直接访问；敏感操作输入一次密码，24 小时内免重复输入，刷新页面也保留。复用现有 `CONFIG_EDIT_PASSWORD`，不增加账号、多角色或数据库会话。OpenAI 兼容地址暂不处理。代码已按本文实施，尚未部署线上。

## 1. 使用体验

- 直接打开网站，正常看行情、图表和首页概况，不弹整站账号密码框。
- 第一次打开敏感管理功能或执行敏感操作时，输入操作密码。
- 后端验证成功，签发有效期 24 小时的安全 Cookie，后续请求由浏览器自动携带，无需反复输入。
- 每次敏感 API 请求，后端都验证 Cookie。绕过页面直接调用接口，仍然必须通过验证。
- 到期或修改密码后重新解锁；主动锁定可清除当前浏览器凭证，普通浏览继续可用。

**一次输入，后端逐次校验。** 前端的“已解锁”标记不能作为授权依据。

## 2. 为什么要改

目前 `POST /api/bot/check-password` 只返回密码验证结果，没有签发后续请求可验证的凭证。`usePageUnlock.ts` 保存的 `localStorage.page_password_verified` 只是界面状态。

策略新建、删除、修改、启停等接口本身没有操作密码校验。紧急加入的 Basic Auth 可以保护这些 API，但会同时拦住普通页面访问，与现在的目标不一致。

改法是把保护放到敏感 API，由后端验证解锁凭证，保留普通访问。

## 3. 保护范围

### 必须验证的操作

| 接口 | 操作 |
| --- | --- |
| `POST /api/strategies` | 新建策略 |
| `PUT /api/strategies/:id` | 修改策略 |
| `DELETE /api/strategies/:id` | 删除策略 |
| `POST /api/strategies/:id/toggle` | 启停策略 |
| `POST /api/strategies/:id/rollback` | 回滚策略 |
| `POST /api/strategies/:id/force-open` | 强制开仓 |
| `POST /api/positions/close` | 手动平仓 |
| `POST /api/bot/config` | 修改全局配置 |
| `POST /api/bot/reload-symbols` | 修改交易对和重载 |
| `POST /api/strategies/:id/test` | 手动分析，可能产生 AI 费用 |
| `POST /api/ai/generate-structured-rules` | AI 规则生成 |
| `POST /api/ai/clear-cache` | 清除缓存 |
| `POST /api/scripts/generate-tv` | 启动服务端脚本 |
| `POST /api/websocket/connect` | 手动初始化外部连接 |

统一规则：**除密码验证入口外，所有 API 的 POST、PUT、PATCH、DELETE 都验证凭证**，避免以后新接口漏保护。其他不支持的方法拒绝执行；GET/HEAD 不允许用于修改配置或交易。

### 普通查看和敏感详情

- 页面、静态资源、行情、K 线、图表、新闻、行情 SSE：直接访问。
- 首页策略名称、运行状态、持仓及收益概况：可以直接展示，只返回页面必要字段。这些公开内容也会被其他访问者看到。
- 完整策略配置、提示词、版本历史、全局配置、完整日志、AI 决策档案、生成脚本文件：使用同一份 Cookie 验证，不需要再次输入密码。

敏感 GET 按具体路由登记，至少覆盖策略详情/版本、`/api/bot/config`、`/api/ai/prompt`、`prompts`、`rules`、`trade-decision` 和 `/api/scripts/get-pine`。

**必须裁剪匿名查询响应。** 当前 `/api/bot/status` 带完整策略和日志，策略列表也带完整配置；不能只保护详情接口，却从首页接口把同样内容返回。密钥对任何访问者都不返回原文。

## 4. 后端最小实现

1. **复用密码。** 使用 `CONFIG_EDIT_PASSWORD`。没有配置时，敏感请求返回 503，不能自动放行；普通浏览继续可用。
2. **签发凭证。** 改造现有密码验证接口，正确时设置 Cookie，错误返回 401。Cookie 包含用途、随机标识、签发/过期时间和 HMAC 签名；用操作密码派生的专用密钥签名，严格校验格式、时间和签名，不能接受客户端自填的解锁状态。
3. **浏览器自动携带。** Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Strict`、`Path=/`，不设 Domain，生产通过 HTTPS。密码和凭证不写入 localStorage 或日志。
4. **固定有效期。** 最长 24 小时，不随轮询延长；修改操作密码后旧签名自动失效。密码不变时，重启不影响未过期凭证。
5. **统一拦截。** 中间件在业务处理、写盘、任务启动、AI 调用和下单前检查全部写接口与敏感 GET；无效凭证返回 401，业务零副作用。
6. **恢复界面。** GET 密码检查接口返回当前请求是否已解锁，不返回凭证；前端刷新后据此恢复状态。增加锁定接口，由后端清 Cookie。
7. **必要防护。** 写请求限定预期 JSON，校验 Origin 为配置的网站来源，拒绝缺失或不可信来源；配合 SameSite 防止跨站借用 Cookie。密码入口同样校验来源，并增加失败限流；敏感请求限制频率和请求体大小。
8. **统一平仓验证。** 平仓接口改用同一 Cookie，取消已经解锁后还要重复传请求体密码的要求。

采用签名 Cookie，无需数据库。简化方案不提供逐设备远程撤销：本机锁定清除本机 Cookie；若 Cookie 被复制，需等待到期或修改密码使所有旧凭证失效。

## 5. 前端最小实现

- 保留现有密码弹窗，验证一次后自动携带 Cookie。
- 页面加载时查询后端解锁状态，不再信任 localStorage 标记。
- 敏感接口返回 401 时提示解锁；普通轮询不反复弹窗。
- 开仓、平仓不因网络错误自动重试；验证失败且尚未执行的操作，由用户确认后继续。
- 锁定或到期后清除已展示的敏感详情，普通页面继续使用。
- 网页授权过期不影响后台自动止损、持仓监控及现有交易风控。

## 6. 改动位置与发布顺序

| 位置 | 改动 |
| --- | --- |
| `server/api/bot/check-password.get.ts`、`.post.ts` | 查询解锁状态、验证密码和签发 Cookie |
| 新增 Cookie 工具和锁定接口 | 统一签名、验证、过期及清除 |
| `server/middleware/00-basic-auth.ts` 或替代中间件 | 从整站门禁改为敏感 API 保护 |
| `bot/status.get.ts`、策略列表及其他匿名查询 | 裁剪配置、提示词、日志等敏感字段 |
| `positions/close.post.ts` | 统一使用 Cookie，取消重复密码要求 |
| `PasswordDialog.vue`、`usePageUnlock.ts` 和相关调用 | 一次解锁、刷新恢复、锁定清理 |
| 配置说明和针对性测试 | 明确密码必填、HTTPS 和接口保护规则 |

先完成新的敏感 API 保护及匿名响应裁剪，再同步取消整站 Basic Auth。`BASIC_AUTH_USERNAME`、`BASIC_AUTH_PASSWORD` 不作为新的操作密码来源，使用已有 `CONFIG_EDIT_PASSWORD`。

发布包含修复的新产物，确认服务器实际加载了密码和中间件；只改 .env 或重启旧 .output 不代表修复已生效。

## 7. 验收标准

- 不输入密码，可以打开页面并正常浏览行情、图表和首页概况。
- 直接请求敏感 API，没有 Cookie 返回 401，配置文件、策略、订单均无变化。
- 正确输入一次后，24 小时内操作和刷新不重复输入，每次敏感请求仍经过后端验证。
- 伪造前端状态、篡改 Cookie、延长有效期、错误密码都不能绕过。
- 密码修改、到期后旧凭证失效；密码为空时敏感 API 拒绝执行。
- 匿名查询不泄露完整策略、提示词、密钥和完整日志；跨站写请求拒绝，猜密码受到限流。
- 使用隔离服务和 mock 验证权限，不以真实开平仓测试；保持后台持仓保护正常。

本次只做：**普通浏览放行、密码一次解锁、敏感 API 后端验证。** 不扩展账号体系、多角色、VPN 或 AI 地址治理。

- 已加入签名 Cookie、24 小时有效期、服务端锁定、跨站写入拦截、登录和写入限流、JSON 请求体限制；客户端禁用自动重试交易，锁定后清理详情和迟到响应。
- 生产配置 `CONFIG_EDIT_PASSWORD` 和 `OPERATION_AUTH_ORIGIN=https://你的实际域名`。来源只含协议、域名及可选端口，不带业务路径；必须 HTTPS。修改环境变量后重新启动加载新产物的进程。

- 登录每分钟 10 次、写操作每凭证每分钟 120 次；JSON 正文上限登录 4 KiB、其他写入 1 MiB。限流不信任客户端转发头，反代下登录按代理连接地址共享；多进程限流各自计数。
