# 币安永续合约 AI 自动交易系统 - 项目运行流程分析

## 1. 项目概述

**项目名称**：币安永续合约 AI 自动交易系统 (Binance Futures AI Trading Bot)

**技术栈**：
- **前端框架**：Nuxt 4 + Vue 3 (Composition API + `<script setup>`)
- **状态管理**：Pinia
- **UI 组件库**：Element Plus
- **图表库**：ECharts + Lightweight Charts
- **后端框架**：Nitro (Nuxt 内置服务端引擎)
- **交易所 SDK**：CCXT (Binance API 封装)
- **AI 模型**：支持 DeepSeek / 豆包 / 阿里千问 / OpenAI
- **技术指标计算**：technicalindicators 库 (RSI, MACD, ADX, ATR, EMA)
- **数据库**：Node.js 内置 `node:sqlite`（用于 K 线数据）
- **数据存储**：JSON 文件系统 + SQLite
- **包管理器**：pnpm

**核心功能**：基于 AI 技术指标分析的币安 USDT 永续合约自动化交易系统，支持多策略并行执行、动态杠杆、智能止损止盈。

### 3.2 关键初始化详细说明

#### 3.2.1 K 线同步服务 (kline-sync.ts)
- 在插件 `plugins/kline-sync.ts` 中初始化
- 先初始化 `data/kline.db`，检查各交易对/周期数据量；缺失数据时执行初始回填，再执行增量同步
- 策略系统完成指标预计算后才调用 `startKLineAutoSync()`，按各周期独立调度；另有高频同步
- 当 K 线数据更新时，通过 EventEmitter 通知 IndicatorsHub
- IndicatorsHub 收到 `klineUpdated` 事件后，自动刷新对应交易对/周期的缓存

#### 3.2.2 仓位管理器插件 (position-manager.ts)
- 插件只负责调用全局 `positionManager.init()` 加载 `data/active-positions.json` 和 `data/symbol-locks.json`
- 交易所持仓同步、状态合并由仓位/策略业务流程负责；策略初始化阶段会再次幂等调用 `init()`

#### 3.2.3 策略管理器插件 (strategy-manager.ts)
- 调用 `initStrategyManager()` 启动完整的策略系统初始化链
- 初始化顺序：BinanceService/配置 → 等待 K 线 ready → IndicatorsHub → PositionManager → StrategyEngine → StrategyManager → 指标初始化/预计算 → 自动同步
- 最后只加载 `isActive=true` 的策略；当前四个策略文件均为 `isActive=false`


3. **HTTP 快照兜底**：超过 10 秒没有有效价格时，低频读取同一内存快照

## 5. 核心模块详解

### 5.1 策略执行引擎 (StrategyEngine)

**文件**：`server/modules/strategy-engine/StrategyEngine.ts` (1362行)

**职责**：
1. 管理多个策略的并发执行
2. 全局定时循环调度（按交易对聚合）
3. 调用 AI 分析（带缓存）
4. 执行交易信号（开仓/平仓）
5. 与仓位管理器协作（同交易对互斥）

**调度机制**：
```
全局定时器 (globalTimer)
     │
     ├── 更新全局扫描间隔 (运行策略最小 scanInterval，向上取整到5分钟倍数)
     │
     ├── 遍历所有运行策略
     │     └── 检查 nextScanTime <= now
     │
     ├── 按交易对分组 (symbol → dueInstances[])
     │
     └── 逐交易对处理:
           ├── 过滤冲突仓位 (hasConflict)
           ├── 构建市场快照 (复用给所有策略)
           └── 分发给每个到期策略
```

**AI 缓存机制**：
- 缓存键：`strategyId_symbol_{指标数据哈希的前32字符}`
- 缓存 TTL：最少10分钟 (可配置 `aiCacheTtlMinutes`)
- 相同的市场数据不重复调用 AI API

**杠杆计算**：
- **固定杠杆**：直接从 `executionConfig.leverage` 读取
- **动态杠杆**：基于置信度超出阈值的比例，线性映射到 `[dynamicLeverageMin, dynamicLeverageMax]`

**仓位大小计算**：
```
riskAmount = 可用余额 × maxRiskPercentage / (入场价 - 止损价) × 入场价
maxUsdtAmount = 可用余额 × maxRiskPercentage × 杠杆
usdtAmount = min(riskAmount, maxUsdtAmount)
```

### 5.2 调度器 (SymbolBasedScheduler)

**文件**：`server/modules/scheduler/SymbolBasedScheduler.ts` (240行)

**核心思想**：先按交易对收集所有订阅的策略，为每个交易对统一构建一次市场快照，然后将快照扇出给所有订阅该交易对的策略。

**优势**：
- 避免重复获取 K 线和指标
- 避免重复调用价格 API
- 更高效的并发控制

**市场快照 (MarketSnapshot)**：
```typescript
interface MarketSnapshot {
  symbol: string
  timestamp: number
  price: number
  indicatorsByTimeframe: Map<Timeframe, Map<string, any>>
  klinesByTimeframe: Map<Timeframe, any[]>
}
```

### 5.3 指标中心 (IndicatorsHub)

**文件**：`server/modules/indicators/IndicatorsHub.ts` (1039行)

**设计**：单例模式，全局唯一实例；交易对来源为 `bot-config.symbols`

**核心功能**：
1. **统一的 K 线缓存**：所有策略共享同一套 K 线数据
2. **按需计算指标**：从缓存 K 线计算指标，避免重复 API 请求
3. **支持的时间周期**：5m / 15m / 1h / 4h / 1d
4. **支持的技术指标**：EMA / RSI / MACD / ATR / ADX
5. **支持的统计指标**：OI (持仓量) / Volume (成交量) / SquareHeat (社交媒体热度)
6. **数据变化自动检测**：通过修改标识跟踪，K 线更新时自动失效缓存
7. **事件驱动更新**：订阅 KLineSimpleSyncService 的 `klineUpdated` 事件
8. **定时刷新循环**：由策略管理器以 60 秒启动刷新；指标预计算另按 `indicatorPrecompute` 配置运行

**K 线数据来源**：从 `data/kline.db` 的 SQLite 缓存加载（通过 `node:sqlite` 和 `kline-simple-storage.ts`）；缓存由 KLineSimpleSyncService 从 Binance 增量更新

### 5.4 仓位管理器 (PositionManager)

**文件**：`server/modules/position-manager/PositionManager.ts` (494行)

**设计**：全局单例

**核心机制**：
1. **Symbol 级别互斥锁**：同一交易对只能被一个策略持有仓位
2. **内存映射**：`positions` (symbol→PositionInfo)、`symbolLocks` (symbol→strategyId)
3. **本地持久化**：写入 `active-positions.json` 和 `symbol-locks.json`
4. **持久化防抖**：100ms 延迟，避免频繁写入
5. **初始化保护**：初始化过程中不持久化，防止覆盖数据
6. **程序启动恢复**：从本地持久化文件恢复仓位和交易对锁；交易所交互在开仓、平仓及监控流程中完成

## 9. 风险控制体系

### 9.1 预筛选 (Pre-Screen)

**文件**：`server/utils/ai-pre-screen.ts`

在调用 AI 分析前，先进行快速过滤：
- **ADX 趋势检查**：需要 ADX > 20 表明有趋势
- **成交量检查**：当前成交量不能异常
- **K 线进度检查**：K线已走时间比例需达标
- 支持策略级覆盖 `preScreenConfig`

### 9.2 信号验证

AI 分析结果需同时满足：
1. 方向不是 `idle`
2. 置信度 >= 策略配置的 `minConfidence`（默认 50）
3. 最终评分 >= `minFinalScore`（默认 0）
4. 风险等级 <= `maxRiskLevel`（默认 HIGH）

### 9.3 仓位风控

1. **最低余额**：可用余额必须 > 30 USDT 才能开仓
2. **最小名义价值**：订单名义价值 >= 20 USDT
3. **动态止损**：基于 ATR × 止损倍率
4. **仓位互斥**：同一交易对只能有一个仓位
5. **最大风险比例**：单笔亏损不超过 `maxRiskPercentage`（如 2%）
6. **止损单**：开仓后立即设置 STOP_MARKET 止损单

### 9.4 AI 缓存与降级

- AI 分析结果缓存 10 分钟以上
- API 失败时返回 `null`，不执行交易
- AI 响应解析失败时安全返回 `idle`

## 14. 应用场景与设计亮点

### 14.1 应用场景
- 币安 USDT 永续合约的自动化趋势交易
- 多策略并行监控不同的交易对
- AI 辅助决策 + 技术指标双重验证
- 7×24 无人值守运行

### 14.2 设计亮点

1. **按交易对聚合调度**：避免重复获取市场数据，提高效率
2. **AI 缓存降级**：相同市场数据不重复调用 AI API，节省成本
3. **Symbol 级互斥锁**：确保同一交易对只有一个仓位
4. **本地持久化**：程序重启后仓位状态不丢失
5. **多 AI 提供商**：灵活切换，防止单点故障
6. **版本控制**：策略修改自动保存历史版本，支持回滚
7. **主题切换**：完整支持明暗双主题
8. **密码保护**：配置修改和敏感操作需要验证
9. **共享轮询**：多个组件共享同一数据流，减少请求量
10. **并发池控制**：AI 调用和指标计算都有并发限制
